# Working with Vaults

This section shows you how to work with a vault like view its content, move files or access it with other applications.

## Unlock Vault {/* #unlock-vault */}

If you want to access the data inside a vault, you have to unlock it by selecting it.

<MobileGrid>
  <Image src="/img/android/unlock-vault-0-select.png" alt="How to unlock a vault with Android" width="810" height="1665" />
</MobileGrid>

In the next step, you have to unlock the vault using the password. If the device supports fingerprint authentication and you've activated it in the settings for this vault, you will be prompted to unlock using fingerprint. How to setup fingerprint authentication will be documented in a separate chapter.

<MobileGrid>
  <Image src="/img/android/unlock-vault-1-using-password.png" alt="How to unlock a vault with Android" width="1080" height="2220" />
  <Image src="/img/android/unlock-vault-2-using-fingerprint.png" alt="How to unlock a vault with Android" width="1080" height="2160" />
</MobileGrid>

After providing the credentials, the vault gets unlocked and opened.

<MobileGrid>
  <Image src="/img/android/unlock-vault-3-loading.png" alt="How to unlock a vault with Android" width="1080" height="2220" />
  <Image src="/img/android/unlock-vault-4-unlocked.png" alt="How to unlock a vault with Android" width="1080" height="2220" />
</MobileGrid>

You're now able to edit the content of the vault.

## Lock Vault {/* #lock-vault */}

To lock an unlocked vault, there are several ways to do this:

* use the lock button in the vault list ①
* use the lock button in the notification ②
* use the lock button in the vault actions ③ and ④

<MobileGrid>
  <Image src="/img/android/lock-vault-0-lock.png" alt="How to lock a vault with Android" width="810" height="1665" />
  <Image src="/img/android/lock-vault-1-notification.png" alt="How to lock a vault with Android" width="810" height="1665" />
  <Image src="/img/android/lock-vault-2-lock-start.png" alt="How to lock a vault with Android" width="810" height="1665" />
  <Image src="/img/android/lock-vault-3-select-lock.png" alt="How to lock a vault with Android" width="810" height="1665" />
</MobileGrid>

All of the possibilities will result in the locked vault.

<MobileGrid>
  <Image src="/img/android/lock-vault-4-finish.png" alt="How to lock a vault with Android" width="1080" height="2220" />
</MobileGrid>

:::note
The auto-lock timeout specified in the settings locks the vault once it hasn't been used for the chosen time. Access by other apps through the [Files app](#access-vault-from-other-apps) also counts as use. Furthermore if not changed in settings, the vault gets locked if the screen turns off. For more information, see [Automatic Locking](settings.mdx#automatic-locking).
:::

## Access Vault from Other Apps {/* #access-vault-from-other-apps */}

Your vaults show up in the Files app of Android and in the system file picker.
Other apps can open, save, create, rename, move, and delete files in a vault directly, without exporting or sharing them first.

To open a vault in the Files app, open the navigation menu and select the entry *Cryptomator* that shows the name of your vault ①.
Every vault has its own entry.
The same entries appear whenever another app asks you to choose a file to open or a location to save to.

<MobileGrid>
  <Image src="/img/android/files-app-0-vaults.png" alt="Vaults in the Files app of Android" width="810" height="1800" />
</MobileGrid>

If the vault is locked, the Files app asks you to sign in to Cryptomator.
Tapping `SIGN IN` ① starts the usual unlock process of Cryptomator with your password or fingerprint.

<MobileGrid>
  <Image src="/img/android/files-app-1-locked.png" alt="How to unlock a vault in the Files app of Android" width="810" height="1800" />
  <Image src="/img/android/files-app-2-unlock.png" alt="How to unlock a vault in the Files app of Android" width="1080" height="2400" />
</MobileGrid>

After unlocking, the Files app shows the content of the vault.

<MobileGrid>
  <Image src="/img/android/files-app-3-unlocked.png" alt="Unlocked vault in the Files app of Android" width="1080" height="2400" />
</MobileGrid>

Cryptomator's own file browser and the Files app work on the same data, so both always show the same state.
To hide your vaults from the Files app, use the setting [Show Vaults in the Files App](settings.mdx#show-vaults-in-the-files-app).

:::note
Changing files in a vault requires write access, the same as in the app itself.
Without the full version, you have read-only access: you can still open files from the Files app, but other apps can't save, create, rename, move, or delete them.
Vaults of a Hub with an active license stay fully writable.
For more information, see [Differences Between Variants and How to Choose](setup.mdx#differences-between-variants-and-how-to-choose).
:::

### Uploads and Conflicts {/* #uploads-and-conflicts */}

When an app saves a file, Cryptomator encrypts it and uploads it in the background.
If the file has been changed in the cloud in the meantime, for example on another device, Cryptomator doesn't overwrite it.
Instead, the save is uploaded as a conflict copy named like `name (ABCDE).ext` next to the original file.
The same applies if you create or upload a file with a name that already exists.

If a vault gets locked while an app still has a file open, the changes are kept on the device and uploaded after the next unlock.

### Failed Changes and Uploads {/* #failed-changes-and-uploads */}

Creating, renaming, moving, and deleting show up in Cryptomator right away.
If the cloud rejects such a change, Cryptomator reverts it and shows the dialog *Change to … failed*.

If an upload fails, Cryptomator doesn't retry it automatically:

* In the Files app, the folder shows the message *An upload in this folder failed. Pull down to retry.* Pull down to retry the upload.
* In Cryptomator, the file shows the message *Upload failed. Tap to retry.* Tap the file to retry the upload.
